## 4. Формализация разности ошибок и парный тест

```text
D_i = |error_baseline_i| − |error_candidate_i|   (общие evaluation pairs)
```

| Параметр расчёта | Значение |
|---|---|
| метод | HAC (лаг = горизонт) либо moving block bootstrap |
| bootstrap: блок | по `target_date`, длина 7 дней, блоки подряд |
| **основной метод p-value** | **HAC с лагом = горизонт** (фиксируется до test) |
| bootstrap | **sensitivity analysis**, не заменяет основной метод; 10 000 репликаций, seed 20261124 |
| перемешивание | запрещено |
| интервал | 95 % |

- Положительное `D` — улучшение кандидата.
- Парный тест выполняется отдельно для варианта A и отдельно для варианта B, на общих парах каждого.
- Исходное p-value каждого сравнения берётся из HAC- или bootstrap-расчёта среднего `D`.

## 5. Holm-коррекция (два основных сравнения)

| Шаг | Правило |
|---|---|
| 1 | вычислить исходные `p_A` и `p_B` для двух основных сравнений |
| 2 | упорядочить по возрастанию: `p_(1) ≤ p_(2)` |
| 3 | **Holm-adjusted p-values (для публикации):** `p_adj_(1) = min(1, 2 × p_(1))`, `p_adj_(2) = max(p_adj_(1), min(1, p_(2)))` |
| 4 | **последовательные пороги Holm** (для процедуры проверки): `α/2`, затем `α`; гипотеза отклоняется при `p_adj_(i) < 0,05` |

Обязательно публикуются: исходные p-value, скорректированные Holm p-value, порядок сравнений и решение по каждому.

**Разделение понятий:** «последовательные пороги Holm» (α/2, α) задают процедуру проверки; «Holm-adjusted p-values» — публикуемая величина, монотонная по рангу: `p_adj_(2) ≥ p_adj_(1)`. Скорректированное значение второго сравнения не может быть меньше первого.

**Статус доверительного интервала:** 95 % CI для среднего `D` — **описательная** метрика (направление и величина эффекта), а не самостоятельный критерий семейной значимости. Решение о статистической значимости принимается только по `p_adj < 0,05`. Нескорректированный CI нельзя использовать как единственное доказательство.

## 6. Критерий «кандидат лучше baseline» (на test, все условия)

1. среднее `D_calendar > 0` (MAE кандидата ниже на общих парах);
2. `p_adj < 0,05` по Holm для соответствующего варианта (A или B);
3. `D_calendar > percentile(D_noise, 95)` — кандидат лучше 95-го перцентиля шумовых прогонов;
4. WAPE не ухудшается более чем на 1 процентный пункт;
5. |Bias| не возрастает;
6. результат воспроизводится на `min_train = 21` или явно признан нестабильным.

## 7. Random-noise control

### 7.1. Определения

```text
D_calendar = MAE_baseline − MAE_calendar
D_noise[j] = MAE_baseline − MAE_noise[j]      для j = 1…100
```

- Положительное `D` означает, что прогноз лучше baseline.
- Критерий: `D_calendar > percentile(D_noise, 95)`.

### 7.2. Генерация шума

| Параметр | Правило |
|---|---|
| PRNG | mulberry32, детерминированный, seed = `j` |
| величина | `amplitude × u_j(d)`, где `u_j(d)` — равномерное число из PRNG |
| знак | из того же PRNG: `u_j(d) < 0,5 → минус`, иначе плюс |
| amplitude | медиана `|поправки|` варианта A на validation, фиксируется до test |
| зависимость от target | шум **не** использует фактические значения целевого дня и не зависит от `actual` |
| округление | нет |

### 7.3. Одинаковые evaluation pairs

- Каждый шумовой прогон оценивается на **том же** множестве пар `(origin_date, target_date)`, что baseline и календарный кандидат.
- Если множества пар не совпадают, сравнение **блокируется**: статус `INCONCLUSIVE`, кандидат не объявляется победителем.

### 7.4. Перцентиль

- 95-й перцентиль вычисляется детерминированно. **Индексация массива — с нуля.** Для 100 отсортированных значений:
  - `position = 0,95 × (100 − 1) = 94,05`;
  - `q95 = sorted_values[94] + 0,05 × (sorted_values[95] − sorted_values[94])` — линейная интерполяция между элементами с индексами 94 и 95.
- Метод фиксируется до test и не меняется.

### 7.5. Сохранение результатов

Для каждого прогона сохраняются: `seed`, `amplitude`, `config_hash`, MAE, WAPE, Bias, checksum результата, число evaluation pairs.

## 8. Обязательные контрольные прогоны

| Прогон | Назначение |
|---|---|
| baseline без поправки | воспроизводимость |
| `alpha = 0` | тождественность baseline (прогноз не меняется) |
| вариант A (пн/сб) | основная гипотеза |
| вариант B (полный профиль) | дополнительная гипотеза |
| 100 шумовых прогонов (seed 1…100) | контроль амплитуды и направления |

## 9. Диагностика дублирования информации (до test)

| Метрика | Формат |
|---|---|
| корреляция `weight(d)` с `rolling_7_day_mean` на origin | r, n |
| распределение поправки | среднее, медиана, p05, p95 в заказах |
| распределение поправки | то же в процентах от уровня |
| стабильность знака по кварталам | доля кварталов с тем же знаком |
| поведение при росте/снижении уровня | средняя поправка по направлению |

- При |r| > 0,8 интерпретация «новая информация» запрещена.

## 10. Правило выбора конфигурации (детерминированное)

1. Основная конфигурация `alpha = 1.0`, `limit = 10 %` регистрируется до запуска.
2. Sensitivity grid оценивается только на validation.
3. Выбор: минимум MAE на validation; при равенстве — меньший `alpha`, затем меньший `limit`.
4. Выбранная конфигурация получает `config_hash`.
5. Test используется один раз; изменение параметров после теста — новый `experiment_id`.

## 13. Ожидаемые исходы

1. кандидат лучше baseline по всем условиям раздела 6 — основание для следующего этапа;
2. различия нет — гипотеза не подтверждена;
3. кандидат хуже — гипотеза отклонена.

Отрицательный результат считается полноценным результатом этапа.
