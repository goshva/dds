# Протокол backtesting (backtesting protocol)

**Статус:** действующий (Stage 3.4.1) · **Версия контракта:** `backtesting/v1` · **Дата:** 2026-11-23

Документ определяет воспроизводимую процедуру проверки моделей. Все будущие модели обязаны проходить эту процедуру целиком.

---

## 1. Rolling-origin evaluation

- Для каждой точки origin:

1. Определить доступную историю: наблюдения `[first_date … origin_date]`.
2. Сформировать обучающий набор (только история; число наблюдений ≥ `min_train_days`).
3. Построить прогноз на шаги `1 … max(horizons)`.
4. Сохранить прогноз и метаданные (модель, origin, шаг, target, статус, причина).
5. Дождаться наличия фактического значения на `target_date`.
6. Рассчитать ошибку и добавить наблюдение в оценочную выборку.

Фактические данные после origin **не могут** использоваться при построении прогноза.

## 2. Разделение данных

| Этап | Доступные данные |
|---|---|
| обучение | только история до `origin_date` включительно |
| прогноз | только даты позже `origin_date` |
| оценка | после появления фактического значения |

Запрещено:

- случайное перемешивание временного ряда;
- обычный случайный train/test split по последовательности дат;
- обучение и оценка на пересекающихся периодах.

## 3. Предотвращение утечки данных (leakage prevention)

- Обязательные проверки для каждого прогноза:

| № | Правило |
|---|---|
| 1 | `target_date > origin_date` |
| 2 | фактическое значение `target_date` недоступно при построении прогноза |
| 3 | признаки строятся только из данных, доступных на `origin_date` |
| 4 | агрегаты и rolling-признаки не захватывают будущие строки |
| 5 | нормализация и преобразования обучаются только на доступной истории |
| 6 | пропуски не заполняются будущими значениями |
| 7 | метаданные эксперимента не содержат будущей информации, влияющей на прогноз |
| 8 | `max(дата истории модели) ≤ origin_date` |

Существующий механизм `assertNoFutureData` (`src/forecasting/baselines/types.ts:64`) сохраняется и используется всеми моделями.

**Известный пробел (зафиксирован, не исправляется на этом этапе):** `assertNoFutureData` проверяет только даты и конечность значений переданной истории. Он не проверяет:

- корректность порядка наблюдений внутри истории (дубликаты дат не отклоняются);
- отсутствие в модели скрытых глобальных статистик, вычисляемых по всему ряду до вызова функции;
- отсутствие утечки через метаданные (например, через признаки, переданные отдельным аргументом).

Эти случаи должны проверяться на уровне модели и на уровне эксперимента; расширение механизма требует отдельного согласования.

## 4. Повторяемость

- Одинаковые входные данные, origin, конфигурация, версия модели, параметры и seed (если применим) обязаны давать одинаковый прогноз в пределах установленной численной точности.

Для каждого запуска фиксируются:

```text
experiment_id, model_id, model_version, config_hash, dataset_checksum,
origin_date, target_date, horizon_step, evaluation_mode, min_train_days,
prediction, actual, error, run_timestamp, status
```

Это спецификация будущего контракта хранения, а не требование внедрить новую систему хранения на текущем этапе.

Существующее подтверждение воспроизводимости: два прогона backtesting дают идентичный `checksum` прогнозов; проверяется CLI-командой `forecast:backtest`.

## 5. Обязательные артефакты прогона

| Артефакт | Содержимое |
|---|---|
| детализация прогнозов | модель, режим, origin, шаг, target, прогноз, факт, ошибка, статус |
| сравнение моделей | метрики по режимам и горизонтам, флаги общей выборки |
| покрытие | origins, прогнозы ожидаемые/сформированные/недоступные, пропущенные факты |
| проверка утечки | перечень правил и нарушений |
| воспроизводимость | checksum первого и второго прогонов, результат независимого пересчёта метрик |

## 6. Запреты

- Менять правила оценки задним числом.
- Исключать неудачные наблюдения без причины и счётчика.
- Заменять отсутствующие прогнозы и факты нулём или интерполяцией.
- Сравнивать модели на существенно разных выборках без статуса `INCONCLUSIVE`.
- Менять `min_train_days` без нового идентификатора конфигурации.

## 7. Связь с реализацией

| Правило | Реализация |
|---|---|
| rolling-origin | `runBacktest` (`src/forecasting/analytics/backtesting/rolling-origin.ts`) |
| шаги и горизонты | `step`, `horizonDays`, `DEFAULT_HORIZONS = [1,3,7,14]` |
| режимы | `evaluationMode: "cumulative" \| "step-exact"` |
| проверка утечки | `LeakageCheck`, `assertNoFutureData` |
| воспроизводимость | `checksumOf(records)`, `runBacktest` × 2 |
| CLI | `bun run forecast:backtest` |

## 8. Ограничения

- Протокол не внедряет новую систему хранения экспериментов и не изменяет существующий pipeline за пределами описанных проверок.
