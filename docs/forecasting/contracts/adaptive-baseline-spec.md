# Спецификация адаптивного baseline (adaptive baseline spec)

**Статус:** проект, требует утверждения · **Версия:** `adaptive-baseline/v2` · **Дата:** 2026-11-24
**Основание:** Stage 3.4.4 и Stage 3.4.4.1 · **Границы:** реализация запрещена до утверждения спецификации и протокола

---

## 1. Цель

- Проверить, даёт ли календарная поправка **дополнительную точность** поверх `rolling_7_day_mean`, а не повторяет ли его информацию.
- Формула гипотезы (не изменяется):

```text
forecast_corrected(d) = forecast_rolling_7(d) + clip(alpha * weight(d), ±limit)
weight(d) = mean_by_day_of_week(history_until_origin) − mean(history_until_origin)
```

- Профиль и уровень вычисляются только по фактическим значениям с датами `≤ origin_date`.

## 2. Иерархия эксперимента

| Уровень | Конфигурация | Роль |
|---|---|---|
| **основной** | `alpha = 1.0`, `limit = 10 %`, горизонт **7**, режим `step-exact`, `min_train = 28`, варианты **A и B** | определяет решение о принятии гипотезы |
| дополнительный | горизонты 1, 3, 14 | проверка переносимости, exploratory |
| дополнительный | `min_train = 21` | sensitivity |
| дополнительный | sensitivity grid `alpha ∈ {0.5, 0.75, 1.0}`, `limit ∈ {5 %, 10 %, 15 %}` | выбор конфигурации только на validation |

Правила:

- Дополнительные результаты **не заменяют** основной критерий.
- Победитель не объявляется по большинству удачных дополнительных метрик.
- Если основной критерий не выполнен, статус — `NO_MATERIAL_DIFFERENCE` или `WORSE`, независимо от дополнительных результатов.

## 3. Контроль множественных сравнений

**Семейство основных сравнений** (фиксировано заранее): `{A, B} × {h = 7} × {min_train = 28}` — два сравнения (кандидат против лучшего baseline на общих парах).

| Элемент | Решение |
|---|---|
| метод коррекции | поправка Holm для двух основных сравнений (уровень значимости 0,05) |
| порядок | по возрастанию p-значения; **adjusted p-values** монотонны: `p_adj_(2) ≥ p_adj_(1)` |
| дополнительные сравнения | exploratory, публикуются без коррекции с явной пометкой |
| запрет | объявлять победителя на основании p-значений без учёта семейства |

p-значение для разности ошибок оценивается по HAC или блочному бутстрэпу (раздел 4); методика фиксируется до теста.

Статус доверительного интервала: 95 % CI для среднего `D` — описательная метрика (направление и величина эффекта). Самостоятельным критерием семейной значимости он не является: решение принимается только по `p_adj < 0,05` после Holm-коррекции для двух сравнений (A и B).

## 4. Формализация разности ошибок

```text
D_i = |error_baseline_i| − |error_candidate_i|   (на общих evaluation pairs)
error_x_i = forecast_x_i − actual_i
```

- Положительное `D_i` означает улучшение кандидата.
- Оценивается среднее `D` и его 95 % интервал.

Расчёт интервала (фиксируется заранее):

| Параметр | Значение |
|---|---|
| метод | HAC (Ньюи–Уэст) с лагом = горизонт, либо moving block bootstrap как альтернатива |
| основной метод p-value | **HAC с лагом = горизонт**, фиксируется до test |
| bootstrap | sensitivity analysis (не заменяет основной метод): блок по `target_date`, длина 7 дней |
| bootstrap: число репликаций | 10 000 |
| bootstrap: seed | 20261124 |
| перемешивание | запрещено: наблюдения не перемешиваются, блоки идут подряд |
| уровень | 95 % |

Для Holm-коррекции p-значение берётся из того же расчёта (двустороннее).

## 5. Контроль случайной поправкой

Определения (направление сравнения фиксировано):

```text
D_calendar = MAE_baseline − MAE_calendar
D_noise[j] = MAE_baseline − MAE_noise[j]      j = 1…100
```

- Положительное `D` означает, что прогноз лучше baseline.
- Критерий: `D_calendar > percentile(D_noise, 95)`.

| Параметр | Значение |
|---|---|
| число прогонов | 100 детерминированных seed: 1…100 |
| генератор | mulberry32, seed = j; величина `amplitude × u_j(d)`, знак из того же PRNG (`u < 0,5` → минус) |
| амплитуда шума | медиана `|поправки|` варианта A на validation, фиксируется до теста |
| зависимость от target | шум не использует фактические значения целевого дня |
| evaluation pairs | те же пары `(origin_date, target_date)`, что у baseline и кандидата; при несовпадении сравнение блокируется (`INCONCLUSIVE`) |
| перцентиль | 95-й, детерминированно, **индексация с нуля**: `position = 0,95 × (100 − 1) = 94,05`; `q95 = sorted[94] + 0,05 × (sorted[95] − sorted[94])` |
| сохраняются | seed, amplitude, config_hash, MAE, WAPE, Bias, checksum, число пар |

- Если `D_calendar <= percentile(D_noise, 95)`, кандидат не проходит шумовой контроль, вывод об эффекте недействителен.

## 6. Диагностика дублирования информации

Обязательные метрики (до основного сравнения):

1. корреляция `weight(d)` с текущим уровнем `rolling_7_day_mean` на origin;
2. распределение поправки в заказах: среднее, медиана, p05, p95;
3. распределение поправки в процентах от текущего уровня;
4. стабильность знака поправки по кварталам;
5. поведение при растущем и снижающемся уровне (направление уровня по данным до origin).

- Формула гипотезы при этом не изменяется.
- Если корреляция высокая (|r| > 0,8), интерпретация «поправка добавляет новую информацию» запрещена.

## 7. Правило выбора гиперпараметров

| Шаг | Правило |
|---|---|
| 1 | основная конфигурация `alpha = 1.0`, `limit = 10 %` зарегистрирована заранее и оценивается первой |
| 2 | sensitivity grid оценивается **только** на validation |
| 3 | выбор внутри grid детерминирован: минимум MAE на validation; при равенстве — меньший `alpha`, затем меньший `limit` |
| 4 | выбранная конфигурация получает `config_hash` |
| 5 | после фиксации test используется **один раз** |
| 6 | изменение параметров после теста создаёт новый `experiment_id` и полный повтор |

- Ручной выбор конфигурации после просмотра тестовых результатов запрещён.

## 8. Базовые решения (не изменяются)

| Параметр | Значение |
|---|---|
| основной baseline | `rolling_7_day_mean` (формула не изменяется) |
| контрольные baseline | `naive_yesterday`, `weekly_seasonal_naive` (не изменяются) |
| минимальная поддержка профиля | 3 наблюдения, иначе `weight = 0` |
| округление | нет, прогноз остаётся дробным |
| варианты | A — понедельник и суббота; B — полный недельный профиль; результаты не смешиваются |

## 9. Ограничения

| Ограничение | Следствие |
|---|---|
| семантика `PROVISIONAL` | результаты технические |
| история 905 дней, два неполных года | устойчивость по годам не гарантирована |
| значимы только пн и сб (HAC) | остальные дни могут давать шум |
| внешние факторы не подключены | праздники, переносы, погода и события не учитываются |
| простая форма поправки | нелинейности и взаимодействия не проверяются |
