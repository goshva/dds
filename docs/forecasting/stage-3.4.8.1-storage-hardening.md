# Упрочнение теневого хранилища (Stage 3.4.8.1)

**Статус:** реализовано · **Версия:** `shadow-mode/v1.1` · **Дата:** 2026-11-24
**Объём:** R1 (fail-closed чтение JSONL) + R2 (межпроцессная блокировка). Контракт снапшота не изменялся.

---

## 1. R1 — fail-closed чтение

```text
readJsonl(path, validate?)
  ├─ файла нет → []            (существующий контракт)
  ├─ пустые строки и завершающий \n допустимы
  ├─ каждая непустая строка → JSON.parse отдельно
  ├─ при первой ошибке → ShadowStorageCorruptedError(file, line, reason)
  ├─ при несоответствии структуры → та же ошибка (reason = структура)
  └─ частичный результат не возвращается
```

- Ошибка содержит имя файла, номер строки и причину; содержимое записей в сообщение не попадает.
- Валидаторы структуры: `isSnapshotRecord`, `isReconciliationRecord`, `isShadowErrorRecord`.
- Все потребители (`appendSnapshot`, `reconcile`, `monitor`) передают валидатор; ошибка распространяется в CLI.
- CLI: `ShadowStorageCorruptedError` → `exit 6`, запись в `errors.jsonl` не выполняется (чтобы не продолжать операцию на повреждённом хранилище).

## 2. R2 — межпроцессная блокировка

| Свойство | Реализация |
|---|---|
| файл | `data/shadow/7745/.shadow.lock` |
| захват | атомарное `openSync(path, "wx")` — проверка «существует → создать» запрещена |
| содержимое | `pid`, `hostname`, `started_at`, `token`, `mode` (без персональных данных) |
| второй запуск | `LOCKED`, без чтения/записи JSONL, exit 4 |
| освобождение | `finally`, только при совпадении `token` |
| повреждённый lock | `CORRUPTED_LOCK`, exit 5, файл сохраняется |
| другой hostname | `STALE_AMBIGUOUS`, автоматическое удаление запрещено, exit 5 |
| активный pid на том же host | `LOCKED`, lock сохраняется |
| завершённый pid на том же host | контролируемое восстановление: atomic `rename` → сверка содержимого → удаление → повторный `wx`-захват |
| гонка | после `rename` путь свободен; конкурентный захват атомарен; при неудаче — отказ |

## 3. Exit codes

| Код | Значение |
|---:|---|
| 0 | успех |
| 1 | ошибка выполнения |
| 2 | checksum canonical CSV не совпал |
| 3 | CONFLICT снапшота |
| 4 | lock занят (`LOCKED`) |
| 5 | неоднозначное/повреждённое состояние lock |
| 6 | повреждённое JSONL-хранилище |

## 4. Совместимость

- `snapshot_id`, формула identity, поля снапшота, форматы JSONL и `manifest.json` не изменены.
- Lock-данные не входят в snapshot identity.
- Модели, baseline и правила режимов не изменены.
- `package.json`, SQLite, canonical CSV не затронуты.
