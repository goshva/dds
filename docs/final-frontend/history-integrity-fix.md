## 3. Исправленный fallback (FACT)

**Было** (`src/web/main.ts`): при недоступности coverage создавался объект вида
`{ firstDate: data.from, lastDate: data.to, days: data.returnedPoints, gaps: 0, duplicateDates: 0, nullValues: 0, nullPolicy: "REJECTED_AS_CORRUPTED", completeness: "UNKNOWN", missingDates: [], gapIntervals: [], maxGapLength: 0, fillRatio: 0, fillRatioFormula: "observationDays / calendarDays" }`
— интерфейс показывал «0 пропусков» и «доля 0,000», то есть имитировал успешную проверку полноты.

**Стало:** `const cov = coverage.status === "ok" ? (coverage as { data: CoverageDto }).data : null;` — никаких синтетических значений; проверка `gaps: 0|fillRatio: 0` в `main.ts` теперь даёт `false`.

**Изменения представления (`src/web/pages/history.ts`):**

| Элемент | Coverage доступен | Coverage недоступен |
|---|---|---|
| Бейдж полноты | `полнота: <completeness>` (OK/PENDING/NOT_AVAILABLE) | `полнота: данные недоступны` (NOT_AVAILABLE) |
| Первая/последняя доступная дата | из API | `[Н/Д]` + статус NOT_AVAILABLE |
| Доступных наблюдений | `coverage.days` | `[Н/Д]`, примечание «coverage API недоступен» |
| Полнота ряда | `доля <fillRatio>` или `[Н/Д]`, формула из API | `[Н/Д]`, примечание «проверка полноты недоступна» |
| Пропуски | `coverage.gaps`, максимальный интервал из API | `[Н/Д]`, примечание «количество пропусков неизвестно» |
| Подзаголовок страницы | период из coverage | «период данных неизвестен (coverage API недоступен)» |

История, показатели периода, график и таблица при недоступном coverage **продолжают работать** — они зависят только от History API.
