## 4. Реализованные функции (FACT)

1. **Блок «Доступные данные»:** период запроса и активный диапазон, первая и последняя доступные даты (из `coverage`), число доступных наблюдений (`coverage.days`), полнота (`coverage.completeness` + доля из `coverage.fillRatio`), пропуски и максимальный интервал, предупреждение «диапазон выходит за доступные данные» при `rangeClamped`.
2. **Пагинация таблицы:** 50 записей на страницу, кнопки «Назад»/«Вперёд», подпись «записи X–Y из N · страница P из Q»; при одной странице — подсказка без кнопок; индекс вне диапазона ограничивается; порядок — от новых к старым.
3. **Разделение величин:** календарные дни, дни с данными, число наблюдений и доля заполненности показываются раздельно, как их отдаёт API; при отсутствии значения — `[Н/Д]`, процент не вычисляется во frontend.
4. **График факта:** линия разрывается на отсутствующих наблюдениях, значения `null` не превращаются в ноль, прогнозная линия не добавляется.
5. **Семантика:** бейдж «Предварительная семантика» (`PROVISIONAL`), предупреждение о неполном периоде, `[Н/Д]` вместо нулей.

## 10. Ограничения

1. **Индeks страницы хранится в памяти** (`historyPageIndex`), а не в hash: deep link открывает первую страницу; изменение hash-контракта не выполнялось сознательно. При смене диапазона или дат индекс сбрасывается.
2. **Ограничение API `limit ≤ 1000`** сохраняется: если выбранный период содержит больше 1000 точек, ответ помечается `truncated`, агрегаты считаются по всему диапазону, а таблица показывает не более 1000 записей — честный статус сохраняется.
3. Мобильная таблица использует внутреннюю прокрутку, а не карточную компоновку.
4. `fillRatio` отображается как доля (например, `0,996`) без пересчёта в проценты во frontend.
