> Production HTML формируют `src/web/components/` и `src/web/pages/`; экранирование — `src/web/lib/format.ts`;
> актуальная документация архитектуры — `src/web/templates/README.md`; эталоны страниц — `docs/ui/reference/`
> (генератор `tools/reference/`). Исторические результаты ниже не изменялись.

**Дата:** 2026-11-27 · **HEAD:** `6e84af17cc1586f425777efb79b62e1086f36f2a`

## 1. Методика

1. Эталоны открывались напрямую из файловой системы (`file://`).
2. Production UI запускался штатным способом: `bun run ui:dev` (Vite) с прокси `/api` на read-only API (`bun run api:start`, проверено `GET /api/health` → 200).
3. Скриншоты снимались реальным браузером `Chromium 159.0.8154.6` (`chrome.exe --headless --disable-gpu --no-sandbox --virtual-time-budget`) — без установки новых зависимостей.
4. Для каждой страницы и ширины сохранены два изображения: `<page>-reference-<width>.png` и `<page>-production-<width>.png`.
5. Дополнительно выполнено объективное сравнение изображений (Pillow): совпадение размеров полотна, доля «непустых» пикселей (ink), корреляция профиля строк (48 полос).
6. Структурный аудит проводился по фактическому коду: `src/web/pages`, `src/web/components`, `src/web/styles`, partials.

## 4. Результаты объективного сравнения (FACT)

`ink` — доля пикселей, отличающихся от преобладающего фона; `row_corr` — корреляция профиля строк эталона и production.

| Страница | Ширина | ink эталона | ink production | row_corr |

| overview | 1024 | 0.238 | 0.321 | 0.271 |
| overview | 768 | 0.224 | 0.130 | −0.218 |

| history | 1024 | 0.238 | 0.321 | 0.480 |
| quality | 1280 | 0.236 | 0.248 | −0.006 |

| provenance | 1280 | 0.236 | 0.033 | 0.472 |
| forecast-quality | 1440 | 0.238 | 0.032 | 0.452 |
| forecast-quality | 1024 | 0.219 | 0.330 | 0.450 |

| forecast-diagnostics | 1280 | 0.236 | 0.033 | 0.474 |

Сводно: `ink` эталонов стабильно 0.219–0.276; `ink` production — 0.032–0.330. Корреляция профиля строк: min −0.290, max 0.511, среднее 0.153. Пар с `ink` production ниже 5 % — 11.

**Ключевое наблюдение:** страница `forecast-quality` при 1024 px имеет `ink` 0.330, а при 1440 и 1280 px — 0.032/0.033. Одна и та же страница с одними данными не может законно различаться так сильно, поэтому наиболее вероятная причина — **захват во время загрузки** (снимок сделан до завершения запросов и отрисовки), а не дефект интерфейса. Причина не подтверждена: изображения моделью не просматривались.

## 6. Ограничения

- изображения не просматривались моделью: выводы об отдельных визуальных дефектах не делались;
- сравнение пикселей ограничено метриками: различие данных (синтетика против реальных значений) законно меняет текст и геометрию, поэтому низкая корреляция сама по себе не является дефектом;
- матрица полная (36 пар), но для 2 пар метрики не измерялись; 11 пар production имеют признаки незавершённой отрисовки;
- шрифты и сглаживание в headless-режиме могут отличаться от пользовательского браузера.

## 7. Общий вердикт

**`ACCEPTED WITH LIMITATIONS`.** Эталоны созданы и пригодны для проверки; измеримое сравнение выполнено на 34 парах из 36. Полноценная визуальная приёмка требует повторной съёмки «пустых» пар с увеличенным бюджетом ожидания и просмотра изображений человеком — это зафиксировано как дальнейший шаг, а не как выполненная проверка.
