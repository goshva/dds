## 1. Исправленные проблемы (P1)

**Дефект:** KPI-карточки независимых метрик и парного сравнения получали `status: "OK"` независимо от `n` и `interpretabilityStatus` — интерфейс мог создавать впечатление подтверждённого качества модели при одном наблюдении.

**Исправление** (`src/web/pages/forecast-quality.ts`):

- добавлена `metricPresentation()` — разделяет три независимых понятия:
  1. **техническая доступность значения** (`value` конечна);
  2. **полнота наблюдений** (`sampleStatus`: `COMPLETE` / `PARTIAL`);
  3. **возможность интерпретации** (`interpretabilityStatus`).
- правила отображения:

| interpretabilityStatus | Значение | Статус | Примечание |
|---|---|---|---|
| `NOT_AVAILABLE` / `NOT_ASSESSED` | `[Н/Д]` | `NOT_AVAILABLE` | «интерпретация недоступна» |
| `INSUFFICIENT` | число | `PENDING` | «описательное значение, недостаточно наблюдений» |
| `LIMITED` | число | `PENDING` | «ограниченная интерпретация» |
| значение `null` | `[Н/Д]` | `NOT_AVAILABLE` | «значение недоступно» |

- зелёный `OK` больше не используется как оценка качества ни в независимых метриках, ни в парном сравнении;
- `COMPLETE` остаётся исключительно статусом технической полноты (карточка «Полнота выборки» с явной подписью «техническая полнота, не статистическая достаточность»);
- числовые результаты вычислительного ядра, смысл MAE/WAPE/Bias и запрет объявления победителя не изменялись.
