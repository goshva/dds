# Контракты HTML-шаблонов (TPL-1)

**Дата:** 2026-11-27 · **HEAD:** `6e84af17cc1586f425777efb79b62e1086f36f2a` · **Область:** `src/web/templates/partials/**` (22 файла)

**Назначение.** Единый источник правил для HTML-partials DSS UI. Partial-шаблоны остаются визуальной спецификацией: production-рендеринг выполняют TypeScript-компоненты из `src/web/components/**`. Документ описывает согласованный синтаксис, типы значений, границы экранирования и контракт каждого partial.

Основание: `docs/ui/templates-inventory.md` (TPL-0).

---

## 1. Общие правила синтаксиса

- `{{value}}` — экранируемое значение: подставляется только через `escapeHtml()`;
- `{{{trustedHtml}}}` — доверенная разметка: значение обязано быть `TrustedHtml`, полученным из компонента или через `trusted()`;
- `{{#condition}}…{{/condition}}` — блок, отображаемый при истинном значении;
- `{{^condition}}…{{/condition}}` — блок, отображаемый при ложном значении;
- `{{#items}}…{{/items}}` — повторение по элементам массива.

Обязательные ограничения:

- имена плейсхолдеров — только camelCase;
- имена в верхнем регистре запрещены;
- вычисления, вызовы функций, арифметика и тернарные операторы внутри шаблонов запрещены;
- новые операторы и конструкции не вводятся;
- неизвестные поля DTO в разметку не попадают.

## 2. Типы значений

| Тип | Где допустим | Правило |
|---|---|---|
| строка, экранируемая | `{{value}}` | подстановка через `escapeHtml()` |
| доверенная разметка | `{{{value}}}` | только `TrustedHtml` от компонента |
| число | `{{value}}` | форматируется до шаблона (`formatNumber`) |
| логический признак | `{{#flag}}` / `{{^flag}}` | управляет блоком |
| перечислимое значение | `{{value}}` | ограничено известным набором (статус, класс, режим, горизонт) |
| производное значение | `{{value}}` или `{{{value}}}` | вычисляется до шаблона |
| массив | `{{#items}}` | элементы — объекты с описанными полями |

## 3. Правила экранирования

1. Любое значение из API, маршрута или пользовательского ввода проходит через `escapeHtml()`.
2. Значения, помеченные в разметке двойными скобками, не могут быть разметкой.
3. Тройные скобки применяются только к слотам из раздела 4.
4. Компонент не передаёт в доверенный слот строку, собранную из недоверенных данных без экранирования.
5. Значения атрибутов экранируются так же, как текстовые.

## 4. Доверенные слоты

Полный перечень имён, допустимых в тройных скобках:

- `{{{sidebar}}}` — разметка боковой панели, формируется `sidebar()`;
- `{{{topbar}}}` — разметка верхней панели, формируется `topbar()`;
- `{{{content}}}` — содержимое страницы, формируется композицией страницы;
- `{{{brand}}}` — блок бренда, формируется `sidebar()`;
- `{{{safeHref}}}` — экранированная ссылка из `safeHref()`;
- `{{{right}}}` — дополнительный блок заголовка или карточки, формируется страницей;
- `{{{body}}}` — тело карточки, формируется страницей;
- `{{{chart}}}` — разметка графика, формируется `lineChart()` или `barChart()`;
- `{{{legend}}}` — легенда графика, формируется страницей;
- `{{{kpiCard}}}` — карточка показателя, формируется `kpiCard()`;
- `{{{statusBadge}}}` — бейдж статуса, формируется `statusBadge()`.

Правила:

- список закрытый: добавление слота требует обновления этого раздела и проверок;
- ни один из перечисленных слотов не используется с двойными скобками;
- произвольная строка в доверенный слот не передаётся.

## 5. Контракт ссылок

- внешние и обычные ссылки — только через `{{{safeHref}}}` (результат `safeHref()`);
- hash-ссылки внутренней навигации — только по allowlist маршрутов: `#history/`, `#forecast-quality/`;
- динамические сегменты hash-ссылок — только перечислимые имена: `key` (набор `all`, `30`, `90`, `180`, `365`), `mode` (`replay`, `shadow`), `horizon` (`1`, `3`);
- произвольные подстановки в URL запрещены: сегмент не может быть значением из API, из свободного ввода или из query-параметра без проверки по перечислению;
- HTML-экранирование не считается проверкой URL: маршрут и сегменты валидируются по allowlist;
- production-маршрутизация (`src/web/routing.ts`) этим документом не изменяется.

## 6. Контракт таблиц

Partial `data/data-table.html`:

- `columns[]` — описание колонок: `key`, `label`, `numeric?`;
- `rows[]` — строки; каждая строка содержит `cells[]`;
- `cells[]` — значения ячеек в порядке колонок: `value`, `numeric?`;
- `columnCount` — число колонок для строки пустого состояния;
- `emptyText?` — текст пустого состояния, отображается в блоке `{{^rows}}`;
- `caption?` — подпись таблицы.

Правила:

- форматирование и бизнес-логика остаются в компоненте;
- значения ячеек экранируются;
- доверенное содержимое ячеек не предусмотрено.

## 7. Контракт SVG-графиков

- геометрия вычисляется в TypeScript: координаты, масштаб, длины, размеры столбцов, точки;
- partial получает подготовленные значения и не выполняет вычислений;
- `charts/line-chart.html`: `width`, `height`, `firstDate`, `lastDate`, `grid[]` (`x1`, `y1`, `x2`, `y2`, `labelY`, `label`), `series[]` (`cssClass`, `path`);
- `charts/bar-chart.html`: `width`, `height`, `bars[]` (`x`, `y`, `barWidth`, `barHeight`, `label`, `value`);
- `charts/sparkline.html`: `width`, `height`, `points` — подготовленная строка точек;
- текстовые подписи экранируются;
- SVG-атрибуты не принимают произвольный пользовательский ввод;
- `path`, `cssClass`, `points` формируются компонентом.

## 8. Контракт состояния загрузки

Partial `states/loading-state.html`:

- `skeletons[]` — подготовленный массив: `width` (число, процент ширины);
- компонент `loadingState({ rows })` формирует массив сам; partial не перебирает `rows` и не вычисляет ширину;
- пустой массив допустим и означает отсутствие скелетонов.

## 9. Контракты shell

- `shell/app-shell.html`: `{{{sidebar}}}`, `{{{topbar}}}`, `{{{content}}}`, `{{#menuOpen}}`;
- `shell/sidebar.html`: `{{{brand}}}`, `sections[]` (`title`, `items[]` с `label`, `safeHref`, `current`, `unsafe`);
- `shell/sidebar-brand.html`: `brandName`, `brandSub` — экранируемые;
- `shell/sidebar-nav.html`: `sections[]` с `{{{safeHref}}}`; признак `unsafe` — производный логический, означает небезопасную ссылку, а не текущий пункт меню;
- `shell/topbar.html`: `title`, `shopNo`, `lastUpdated`, `sourceStatus`, `sourceStatusClass`, `{{#menuOpen}}` — все значения экранируемые, классы производные;
- `shell/page-header.html`: `title`, `subtitle?`, `{{{right}}}`.

## 10. Контракты partials уровня страницы

`pages/history-filters.html` — соответствует функции `historyFilters()` из `src/web/pages/history.ts`:

- обязательное: `ranges[]` (`key`, `label`, `badgeClass`);
- необязательные: `from`, `to` — значения полей дат, экранируются;
- `key` — только из набора `all`, `30`, `90`, `180`, `365`; ссылка строится как `#history/<key>`;
- валидация диапазона остаётся в компоненте и на сервере.

`pages/forecast-mode-switcher.html` — переключатели режима и горизонта:

- обязательные: `modes[]` (`mode`, `horizon`, `label`, `badgeClass`), `horizons[]` (`mode`, `horizon`, `badgeClass`);
- `mode` — только `replay` или `shadow`; `horizon` — только `1` или `3`;
- ссылка строится как `#forecast-quality/<mode>/<horizon>`;
- отдельной функции-компонента нет: разметка описана как контракт для будущего адаптера страницы (NOT_IMPLEMENTED в production).

## 12. Ограничения шаблонной системы

- partials не исполняются в runtime: production использует TypeScript-компоненты;
- условные блоки и повторения поддерживаются соглашением о синтаксисе, а не движком;
- вычисления, вызовы функций и фильтры внутри шаблонов отсутствуют;
- частичное расхождение с production-кодом фиксируется как NOT_IMPLEMENTED, а не устраняется изменением компонентов на этом этапе;
- шаблоны не описывают данные, которых нет в API.

## 15. Уточнение правил hash-ссылок (TPL-1.1)

Позиционные правила: маршрут, число сегментов, допустимые placeholder-имена и литеральные значения.

| Маршрут | Сегментов | Позиция 1 | Позиция 2 |
|---|---:|---|---|
| `#history/` | 1 | `key`: `all`, `30`, `90`, `180`, `365` | — |
| `#forecast-quality/` | 2 | `mode`: `replay`, `shadow` | `horizon`: `1`, `3` |

Отклоняются: посторонние маршруты, недопустимые значения, пустые сегменты, лишние сегменты, query-строка и процентное кодирование, управляющие символы, схемы (`javascript:`, `https:`), протокол-относительные ссылки (`//`), а также значения в другом регистре.

Динамический сегмент допускается только как `{{key}}`, `{{mode}}` или `{{horizon}}` в своей позиции. Значение из API, свободный ввод и query-параметр в сегмент не подставляются.

## 16. Ограничения автоматических проверок

- проверки partials выполняются регулярными выражениями и структурными сравнениями, без HTML-парсера и без новых зависимостей;
- проверяется соответствие разметки контракту, а не отрисовка в браузере;
- позиционные правила hash-ссылок реализованы тестовым валидатором `checkHashHref`; он проверяет строку ссылки, но не фактическую навигацию;
- расхождение production-кода и контракта фиксируется документально; изменение страниц и компонентов вне allowlist этапа не выполняется;
- проверка не заменяет визуальную проверку (TPL-3) и не подтверждает паритет с TypeScript-рендерингом.
