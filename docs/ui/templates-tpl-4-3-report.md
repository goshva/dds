## 6. Проверка безопасности (FACT)

- **Trusted slots (11):** `sidebar`, `topbar`, `content`, `brand`, `safeHref`, `right`, `body`, `chart`, `legend`, `kpiCard`, `statusBadge` — закрытый перечень; проверяется совпадение документа, тестов и фактического использования, а также запрет двойных скобок для этих имён.
- **URL safety:** `safeHref` допускает `#`, относительные пути и `http(s)`; блокирует `javascript:`, `data:`, `vbscript:`, `file:`, протокол-относительные ссылки и управляющие символы. Hash-ссылки ограничены allowlist маршрутов и перечислимыми сегментами.
- **Escaping:** значения API проходят `escapeHtml` внутри компонентов; частичные файлы используют `{{value}}` и только 11 объявленных доверенных слотов в тройных скобках.
- **Дефект `historyFilters()` (P2, не исправлялся):** `src/web/pages/history.ts:41-53` подставляет `from`/`to` в `value="…"` без `escapeHtml`. Проверка вызывающей стороны: `main.ts:117` вызывает `rangeToQuery` (`routing.ts:136-137`), который пропускает только календарно-реальные даты через `isValidCalendarDate` (`routing.ts:111`); при несоответствии отображается состояние ошибки, фильтры не рендерятся. Дополнительно есть серверные проверки дат (`tests/server/hardening.test.ts:83-87`). Инъекция атрибута практически недостижима, но защита зависит от вызывающей стороны, а не от самой функции.
- **Рекомендация (отдельная задача, вне TPL-4.3):** добавить `escapeHtml(from)` и `escapeHtml(to)` в `historyFilters()` (файл `src/web/pages/history.ts`), либо валидировать значения внутри функции; после правки — тест на экранирование `"`, `<`, `>`, `'`, `&` в обеих ветках (пустое значение и дата).
- Иных дефектов безопасности в рамках этапа не выявлено.
