## Стратегия

Expand → backfill → validate → switch → contract. Новые таблицы/колонки — сначала nullable.
Backfill только из разрешённых источников и после отдельного разрешения. Старые поля не удаляются.
Для финансовых данных предпочтительны компенсирующие операции, а не destructive rollback.
Повторный запуск безопасен или корректно отклоняется; каждая миграция имеет номер и checksum.
