# 19. Безопасность, PII и доступы

## Политики

| ID | Объект | Политика | Роли |
|---|---|---|---|
| PII-01 | Адрес доставки | Виден только ролям, участвующим в доставке; выгрузки ограничены | COURIER, CURATOR, OPERATIONS_MANAGER, GEO_MANAGER |
| PII-02 | ФИО курьера | Хранить display_name; HR-поля отделены от операционного контура | HR, OPERATIONS_MANAGER |
| PII-03 | Телефон/ИНН курьера | Не переносить в новую модель без основания; в отчёты и fixtures не включать | HR (ограниченно) |
| PII-04 | mentorfio | Не переносить в отчёты; сопоставлять по mentorid | Mentorship |
| PII-05 | customer_reference | Псевдоним/внешняя ссылка вместо ФИО | Operations |
| PII-06 | Финансовые начисления | Доступ только уполномоченным ролям | FINANCE, OPERATIONS_MANAGER |
| PII-07 | Логи и события payload | Не хранить секреты и лишние ПДн; payload валидируется схемой | ALL |
| PII-08 | Fixtures и тесты | Только синтетические данные | DEV |
| PII-09 | Экспорт | Учитывать роль пользователя и назначение выгрузки | ADMIN |
| PII-10 | Секреты | Не попадают в логи, отчёты и репозиторий | ALL |

## Роли для проектирования

`ADMIN`, `OPERATIONS_MANAGER`, `GEO_MANAGER`, `CURATOR`, `DISPATCHER` (если утверждён), `COURIER`, `HR`, `FINANCE`, `READ_ONLY_ANALYST`.

`DISPATCHER` не меняет состав ходки, пока действует правило «только куратор».

## Запреты

- PII в fixtures, тестовых отчётах, примерах и логах.
- Секреты в логах и репозитории.
- Собственная система паролей при наличии identity provider.
