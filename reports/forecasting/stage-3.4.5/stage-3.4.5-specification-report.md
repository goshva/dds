## 2. Уточнения по шумовому контролю

```text
D_calendar   = MAE_baseline − MAE_calendar
D_noise[j]   = MAE_baseline − MAE_noise[j]      j = 1…100
Критерий:    D_calendar > percentile(D_noise, 95)
```

| Параметр | Решение |
|---|---|
| генерация | mulberry32, seed = j; величина `amplitude × u_j(d)`; знак из того же PRNG (`u < 0,5` → минус) |
| воспроизводимость | 100 детерминированных seed: 1…100 |
| амплитуда | медиана `|поправки|` варианта A на validation, фиксируется до test |
| зависимость от target | шум не использует фактические значения целевого дня |
| evaluation pairs | те же пары `(origin_date, target_date)`; при несовпадении сравнение блокируется (`INCONCLUSIVE`) |
| перцентиль | детерминированно: сортировка 100 значений, позиция `0,95 × (n − 1) = 94,05`, линейная интерполяция между 94-м и 95-м значениями |
| сохранение | `seed`, `amplitude`, `config_hash`, MAE, WAPE, Bias, checksum, число пар |

- Ранее формулировка «кандидат лучше 95-го перцентиля шумовых MAE» допускала разное направление сравнения. Теперь знак фиксирован: положительное `D` означает преимущество над baseline, и сравниваются однонаправленные величины.

## 3. Holm и доверительные интервалы

| Элемент | Решение |
|---|---|
| семейство | два основных сравнения: A и B на горизонте 7, `min_train = 28` |
| парный тест | отдельно для A и для B на общих парах; исходное p-value из HAC или блочного бутстрэпа |
| Holm | `p_adj_(1) = min(1, 2 × p_(1))`, `p_adj_(2) = min(1, p_(2))`; последовательное применение |
| правило решения | гипотеза отклоняется при `p_adj < 0,05` |
| публикация | исходные p-value, скорректированные Holm p-value, порядок сравнений и решение по каждому |
| доверительный интервал | **описательная** метрика направления и величины эффекта; самостоятельным критерием семейной значимости не является |
| запрет | объявлять победителя при `p_adj >= 0,05`; использовать нескорректированный CI как единственное доказательство |

## 8. Финальное исправление статистического протокола (последний раунд)

### 8.1. Holm-adjusted p-values исправлены

Ранее публикуемая формула `p_adj_(2) = min(1, p_(2))` была некорректной как *adjusted p-value*: при `p_(1) ≤ p_(2)` она могла дать `p_adj_(2) < p_adj_(1)`. Исправлено:

```text
p_adj_(1) = min(1, 2 × p_(1))
p_adj_(2) = max(p_adj_(1), min(1, p_(2)))
Reject H_i if p_adj_i < 0,05
```

Разделены понятия:

| Понятие | Назначение |
|---|---|
| последовательные пороги Holm (`α/2`, затем `α`) | процедура проверки гипотез |
| Holm-adjusted p-values | публикуемая величина; монотонна по рангу |

### 8.2. Индексация перцентиля зафиксирована

```text
sorted_values — индексы 0…99
position = 0,95 × (100 − 1) = 94,05
q95 = sorted_values[94] + 0,05 × (sorted_values[95] − sorted_values[94])
```

В документах явно указано: индексация массива начинается с нуля; интерполяция — линейная, между элементами с индексами 94 и 95.

### 8.3. Основной метод p-value закреплён заранее

| Метод | Статус |
|---|---|
| HAC с лагом = горизонт | **основной**, фиксируется до test |
| moving block bootstrap | sensitivity analysis, не заменяет основной результат |

Выбор метода после просмотра test-результатов запрещён.

### 8.4. Числовые тесты

Числовые проверки вынесены в контрактный тест [statistics-contract.test.ts](../../../tests/forecasting/statistics-contract.test.ts): эталонные реализации формул объявлены локально внутри теста. Отдельный исходный модуль `statistics.ts` удалён как вышедший за согласованный scope (см. раздел 9).
