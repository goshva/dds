# Этап 5 — Протокол backtesting (резюме)

**Документ:** [backtesting-protocol.md](../../../docs/forecasting/contracts/backtesting-protocol.md) · **Версия:** `backtesting/v1`

## Процедура rolling-origin

- Для каждой точки origin: определить историю → сформировать обучающий набор (`≥ min_train_days`) → построить прогноз на шаги `1…max(horizons)` → сохранить прогноз и метаданные → дождаться факта → рассчитать ошибку → добавить наблюдение в оценочную выборку.

## Разделение данных

| Этап | Данные |
|---|---|
| обучение | только до `origin_date` включительно |
| прогноз | только даты позже `origin_date` |
| оценка | после появления факта |

Запрещено случайное перемешивание временного ряда и случайный train/test split по датам.

## Предотвращение утечки (8 правил)

- `target_date > origin_date`; факт целевой даты недоступен; признаки только из данных на origin; rolling-признаки без будущих строк; нормализация обучается только на истории; пропуски не заполняются будущими значениями; метаданные не содержат будущей информации; `max(дата истории) ≤ origin_date`.

Существующий механизм `assertNoFutureData` (`src/forecasting/baselines/types.ts:64`) сохраняется без изменений.

**Зафиксированный пробел:** механизм проверяет только даты и конечность значений. Он не отклоняет дубликаты дат внутри истории и не защищает от глобальных статистик, вычисленных по всему ряду до вызова. Расширение механизма — за границами Stage 3.4.1, требует отдельного согласования.

## Повторяемость

- Одинаковые входы, origin, конфигурация и версия модели дают одинаковый прогноз. Фиксируются: `experiment_id`, `model_id`, `model_version`, `config_hash`, `dataset_checksum`, `origin_date`, `target_date`, `horizon_step`, `evaluation_mode`, `min_train_days`, `prediction`, `actual`, `error`, `run_timestamp`, `status` — как спецификация будущего контракта хранения.

Подтверждено фактически: два прогона `forecast:backtest` дают идентичный checksum прогнозов.

## Артефакты прогона

- Детализация прогнозов, сравнение моделей, покрытие, проверка утечки, воспроизводимость.

## Связь с реализацией

- `runBacktest`, `LeakageCheck`, `checksumOf(records)`, CLI `bun run forecast:backtest`.
