# Этап 1 — Контракт стратегии прогнозирования (резюме)

**Документ:** [forecast-strategy-contract.md](../../../docs/forecasting/contracts/forecast-strategy-contract.md) · **Версия:** `strategy/v1`

## Что зафиксировано

| Раздел | Содержание |
|---|---|
| Объект прогнозирования | `delivered_orders_daily`, univariate, один магазин `7745`, день, Europe/Moscow, единица — заказы |
| Горизонты | `h = 1, 3, 7, 14` с назначением каждого; объединение горизонтов в одну метрику запрещено |
| Термины времени | `origin_date`, `target_date`, `horizon_step`, `forecast_created_at`, `training_window` |
| Правило доступа к данным | для шага `h` доступна только информация на `origin_date` |
| Стратегия выбора модели | независимо для каждого горизонта; стартовые кандидаты зафиксированы как гипотеза |
| Управление версиями | перечень изменений, требующих новой версии контракта |

## Зафиксированные ограничения

1. Целевая переменная — только количество доставленных заказов; денежные метрики, курьеры и слоты в неё не входят.
2. Статус бизнес-семантики `PROVISIONAL` сохраняется; повышение до `CONFIRMED` без письменного подтверждения запрещено.
3. Результаты Stage 3.3.6 — исходная точка сравнения, а не доказательство производственного превосходства.
4. Одна универсальная модель для всех горизонтов не назначается.

## Связь с кодом

- Целевой ряд берётся из canonical CSV (`data/processed/forecasting/7745/canonical_daily_delivered_orders.csv`, 905 дней, checksum `d413286e…`); даты и шаги формируются функциями `addDaysIso` / `targetDates` (`src/forecasting/baselines/types.ts`).
