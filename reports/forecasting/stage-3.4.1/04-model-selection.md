# Этап 4 — Контракт выбора модели (резюме)

**Документ:** [model-selection-contract.md](../../../docs/forecasting/contracts/model-selection-contract.md) · **Версия:** `selection/v1`

## Обязательные условия допуска кандидата (все десять)

- Документированная формула · фиксированная конфигурация · воспроизводимый запуск · отсутствие доступа к будущим данным · корректные даты прогнозов · отсутствие `NaN`/`Infinity` · документированное поведение при недостатке истории · определённые правила обработки пропусков · сравнение с baseline на сопоставимой выборке · идентификатор версии алгоритма и конфигурации.

Нарушение любого условия → модель не допускается к оценке качества.

## Сравнение с baseline

- В сравнение включаются `MAE`, `RMSE`, `WAPE`, `Bias`, число прогнозов, число общих наблюдений, абсолютная и относительная разница MAE, список исключённых наблюдений, а также `margin_to_runner_up` (преимущество относительно ближайшего конкурента).

```text
relative_mae_change = (candidate_mae − baseline_mae) / baseline_mae × 100
```

## Статусы

| Статус | Значение |
|---|---|
| `BETTER` | улучшение по основной метрике на сопоставимой выборке |
| `WORSE` | ухудшение |
| `NO_MATERIAL_DIFFERENCE` | различие недостаточно для практического вывода |
| `INCONCLUSIVE` | мало данных или нарушена сопоставимость |
| `NOT_AVAILABLE` | сравнение невозможно |
| `INVALID` | нарушены обязательные условия допуска |

Численное определение `NO_MATERIAL_DIFFERENCE` **не устанавливается** на Stage 3.4.1: требуется отдельная политика практической значимости на основе бизнес-требований и статистической оценки.

## Производственное назначение

- Статус `PRODUCTION_APPROVED` невозможен без: подтверждённой бизнес-семантики, достаточной истории, воспроизводимого backtesting, стабильности результата, отсутствия существенных проблем с `Bias` и подтверждения владельца продукта.

## Запрет подгонки под тест

- Не подбирать гиперпараметры по тестовой выборке; не менять формулу после просмотра результата без нового идентификатора эксперимента; не скрывать неудачные эксперименты; фиксировать все проверенные конфигурации; отделять исследование от итоговой оценки.
