# Этап 2 — Контракт оценки (резюме)

**Документ:** [evaluation-contract.md](../../../docs/forecasting/contracts/evaluation-contract.md) · **Версия:** `evaluation/v1`

## Обязательные параметры

```text
evaluation_mode = step-exact        (основной)
primary_min_train_days = 28         (основной)
sensitivity_min_train_days = 21     (sensitivity analysis)
horizons = [1, 3, 7, 14]
cumulative                          (только справочный режим)
```

## Ключевые правила

1. Ключ наблюдения — `(origin_date, target_date, horizon_step)`; для `step-exact` требуется `horizon_step = h`.
2. Условия включения: допустимый прогноз, доступный факт, точный шаг, соблюдение обучающего окна, отсутствие утечки, прохождение правил качества.
3. Сопоставимость: сравнение только на общих парах `(origin_date, target_date)`; отсутствующий прогноз не подставляется, не интерполируется и не заменяется нулём.
4. Публикуются: число прогнозов, число общих наблюдений, число исключённых наблюдений и причины.
5. `cumulative` не подписывается как качество прогноза на `h`-й день и не используется для выбора модели.
6. Статусы доступности: `AVAILABLE`, `NOT_AVAILABLE` (не ошибка модели), `INVALID` (нарушение требований, не маскируется под `NOT_AVAILABLE`).
7. `min_train=28` и `min_train=21` не смешиваются ни в одной таблице.
8. **Правило ближайшего конкурента:** практическое преимущество измеряется через `margin_to_runner_up = MAE_best / MAE_second_best − 1`, а не через отрыв от худшей модели (зафиксировано по итогам приёмки Stage 3.3.6).

## Связь с реализацией

- `evaluationMode`, фильтр `record.step === horizon`, `notAvailable[]`, `leakage` — в `src/forecasting/analytics/backtesting/rolling-origin.ts`; публикация режимов — в `reports.ts`.

## Не установлено сознательно

- Численное определение `NO_MATERIAL_DIFFERENCE` не вводится: для него требуется отдельная политика практической значимости, основанная на бизнес-требованиях и статистической оценке.
